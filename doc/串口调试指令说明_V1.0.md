# FloraMate 串口调试指令说明 V1.0

## 1. 串口参数

| 项目 | 值 |
|---|---|
| 接口 | `USART1`，PA9 TX / PA10 RX |
| 波特率 | 115200 |
| 格式 | 8N1，无流控 |
| 行结束 | `\r`、`\n`、`\r\n`，或 **USART IDLE**（一帧发送结束，约 1 字符时间无新数据）自动提交 |

## 2. 上电与串口调试入口（HMI V2.0）

> **V2.0 起**产品路径为 **Logo → Idle 5s → 自动浇水 / 主界面**，不再使用旧版 10s Boot Wait。  
> 完整流程见 [`上电运行分支与操作逻辑_V2.0.md`](上电运行分支与操作逻辑_V2.0.md)。

### 2.1 产品路径中的串口入口

| 情况 | 行为 |
|---|---|
| **Idle 5s 内**收到 `debug` / `debug on` / `dbg` | 进入**串口调试**；OLED 显示命令与结果；**串口不再打印心跳**（LED 心跳灯仍 500ms 闪烁） |
| Idle 内 **K1+K3 按住 2s** | 进入**主界面**（非串口） |
| Idle **5s 超时**无操作 | **自动浇水**（`AUTO_RUN`） |
| **设置 → Serial Test** | 进入串口调试（与 Idle 入口相同 UI） |
| 串口调试 **K4 长按 2s** 或 `debug off` / `exit` / `quit` | 退出串口调试；**从 Idle 进入 → 回主界面**；**从设置进入 → 回设置页** |
| 自动浇水中 **K4** | **紧急停止** → 完成页 `STOPPED` → K4 回主界面 |
| 编译宏 `APP_SERIAL_DEBUG_AUTO_ENTER_ON_BOOT=1` | **跳过 Logo/Idle**，上电直接进入串口调试（联调用） |

Idle 期间串口每秒输出心跳（`wait_remain_ms` 为 Idle 剩余毫秒，示例）：

```text
[I] hb uptime_ms=1000 wait_remain_ms=4000
```

进入自动流程后心跳不带倒计时：

```text
[I] hb uptime_ms=15000
```

进入调试后打印 `[I] serial debug active (no hb)` 与 `help`；此后**串口不再打印心跳**，LED 心跳灯仍 500ms 闪烁。

OLED：

- **Logo / Idle**：版本行、Idle 倒计时 `5…1`
- **Serial Debug**：`> 当前命令`、`OK:` / `ERR:` 结果、PWM 与 5 路阀（Z1~Z5）状态位
- **Key Test**（`key test` 后）：四行 `K1 UP` / `K2 DOWN` / `K3 OK` / `K4 BACK`，按下 `ON`（反白），松开 `--`；`key test off` 退出

> **历史说明：** `APP_SERIAL_DEBUG_BOOT_WAIT_MS`（10s）与 K1+K2 进手动选择为 **V1.1 遗留**，V2.0 产品路径不再使用；宏仍保留于 `app_serial_debug_config.h` 供兼容参考。

## 3. 编译开关

文件：`flora_mate/code/App/serial_debug/app_serial_debug_config.h`

```c
#define APP_SERIAL_DEBUG_BOOT_WAIT_MS (10000U)  /* V1.1 遗留；V2.0 Idle 固定 5s，见 app_main_fsm.c */
#define APP_MODE_MANUAL_COMBO_HOLD_MS (2500U)   /* V1.1 遗留：K1+K2 进手动选择 */
#define APP_SERIAL_DEBUG_K4_EXIT_HOLD_MS (2000U) /* 串口调试 K4 长按退出 */

#ifndef APP_SERIAL_DEBUG_AUTO_ENTER_ON_BOOT
#define APP_SERIAL_DEBUG_AUTO_ENTER_ON_BOOT (0) /* 1=上电自动进 debug */
#endif
```

## 4. 命令总览

| 命令 | 说明 |
|---|---|
| `debug` / `debug on` / `dbg` | 进入手动-串口（等待窗内或已调试态均可） |
| `debug off` / `exit` / `quit` / `manual exit` | 退出手动-串口，回到 Boot Wait（等待窗重计；超时走自动） |
| `help` / `?` | 打印命令帮助 |
| `ver` | 打印固件版本、硬件版本和编译时间 |
| `status` | 打印主状态、PWM、阀状态、UART 计数 |
| `key test` / `keytest` | 进入按键测试：OLED 实时显示 K1~K4 是否按下；串口在状态变化时打印 `keys k1=...` |
| `key test off` / `key test exit` / `keytest off` | 退出按键测试，回到普通串口调试界面 |
| `pump <0-100>` | 设置水泵 PWM 占空比（实际夹到 ≤95%）；须至少一路阀（Z1~Z5）已开 |
| `pump off` | 水泵 PWM 置 0（停泵） |
| `valve open <1-5>` | 打开指定电磁阀 Z1~Z5，**不关闭其它路**（可多路同时 on） |
| `valve close` | 关闭全部 5 路阀 |
| `valve close <1-5>` | 关闭指定阀 |
| `cfg dump` | 打印当前 RAM 全部配置（含软硬件版本号） |
| `cfg get`（无参数） | 读取全部配置，等价于 `cfg dump` |
| `cfg get <name>` | 读取单个配置字段 |
| `cfg set <name> <value>` | 修改 RAM 中的配置字段（提示需 `cfg save` 落盘） |
| `cfg save` / `cfg load` | 保存、重载配置 |
| `cfg reset` | 恢复出厂设置（**二次确认**：需再输入 `y`） |
| `stop` | 立即关 PWM 并关闭全部阀 |
| `run` | 预留；本阶段不启动自动浇灌 |
| `reset` | MCU 软件复位 |

### 阀用户编号（`valve` 命令，对应 BSP 通道 Z1~Z5 / PA1~PA5）

| 编号 | BSP 通道 | 引脚 | 说明 |
|---|---|---|---|
| 1~4 | Z1~Z4 | PA1~PA4 | 四路电磁阀 |
| 5 | Z5 | PA5 | 备用阀（与 Z1~Z4 等价） |

`pump` 命令仅控制水泵 PWM 调速（PA0），**不再有独立的水泵电源通道**；占空比非 0 时要求至少一路阀已开（软件干转互锁）。

调试模式下 `valve open/close` 走 `Bsp_Valve_DebugSet()`，**无互锁**，可同时打开多路。

### cfg 配置读写命令详解

#### 读取全部配置

```text
cfg dump
cfg get          ← 无参数，等价于 cfg dump
```

两者都会在串口**逐项打印全部配置字段**（含软件版本 `fw` 与硬件版本 `hw`）：

```text
[I] ==== config dump ====
[I] fw=FloraMate V1.0  hw=3.1
[I] src=bank_a  update_count=3
[I] n_steps=4  ch_en=0x1F  idle=3s  gap=500ms
[I]   duty[0]=35%  sec[0]=3s
[I]   duty[1]=55%  sec[1]=3s
[I]   duty[2]=75%  sec[2]=3s
[I]   duty[3]=95%  sec[3]=3s
[I] tmo_ch=90s  tmo_all=480s  selftest=50ms
[I] long=1000ms  hold=3000ms  contrast=128  log=2
[I] ==== config dump end ====
```

- `fw`：软件版本（Flash 常量，`ver` 命令同源）
- `hw`：硬件版本号（EEPROM 配置区 `hw_version` 字段，BCD 解码；当前 V3.1）
- `src`：当前配置加载来源（`factory` / `bank_a` / `bank_b`）
- `update_count`：累计保存次数（诊断 EEPROM 损耗）

#### 读取单个字段

```text
cfg get <name>      → [I] <name>=<value>
cfg get duty[2]     → [I] duty[2]=75
cfg get log         → [I] log=2
```

字段名见下表（短别名），每项含义与默认值：

#### 浇灌阶梯参数（定义一次自动浇水的 PWM 曲线）

| 短名 | C 字段 | 默认 | 范围 | 含义 |
|---|---|---|---|---|
| `n_steps` | `step_count` | 4 | 1~8 | **阶梯档数**：一次自动浇水分成几个阶段（档）来供水。默认 4 档 = 分 4 个阶段。用多档的目的是让水泵**渐进升压/降压**（例如 35%→55%→75%→95% 缓慢加力），避免水泵突然满功率启动的水锤冲击；浇灌结束再逐档递减（95%→75%→…）平稳收水 |
| `duty[i]` | `step_duty[i]` | 35/55/75/95（档 0~3），其余 0 | 0~95 | **第 i 档占空比**：该档水泵的输出强度，单位 %。**占空比** = 每秒钟内水泵"通电时间"占比：100% 表示全速、50% 表示半速、0% 表示停转。0 表示该档不输出（可作"间歇停水"）；上限钳位到 95%（而非 100%）是为水泵留保护余量，避免长时间满额定运行 |
| `sec[i]` | `step_seconds[i]` | 3（档 0~3），其余 0 | 0~60 | **第 i 档持续秒数**：该档维持多少秒再进入下一档。与 `duty[i]` 一一配对（第 i 档以 `duty[i]` 的强度跑 `sec[i]` 秒）；`sec[i]=0` 的档位跳过不执行 |
| `ch_en` | `channel_enable` | 0x1F | 0x01~0x1F | **启用通道位图**：控制 5 路电磁阀 Z1~Z5 哪些参与自动浇灌。bit0 对应 Z1、bit1 对应 Z2、…、bit4 对应 Z5，置 1 表示该路启用。常用值：`0x1F`（二进制 11111）= 5 路全开；`0x01`= 仅 Z1；`0x03`= 仅 Z1+Z2。写入时用十六进制或十进制均可（`cfg set ch_en 31` 等价 `0x1F`） |

> **浇灌执行顺序**（完整流程）：按 `ch_en` 中置位的阀，从 Z1 到 Z5 逐路浇灌 → 每路内部按 `n_steps` 个阶梯依次执行（第 i 档以 `duty[i]` 强度跑 `sec[i]` 秒）→ 两路之间插入 `gap_ms` 静默 → 全部浇完结束。

#### 时序参数（定义浇灌节奏与安全时限）

| 短名 | C 字段 | 默认 | 范围 | 含义 |
|---|---|---|---|---|
| `idle` | `idle_seconds` | 3 | 1~30 | **上电倒计时**（秒）：设备上电后**不立即浇灌**，而是先等待这段时间（默认 3 秒），给用户一个"反悔"的机会——这期间可以通过串口发 `debug`、按键或其它方式介入，取消/改写本次自动浇灌。倒计时结束且无操作，才正式进入自检和浇灌。设短一点响应快，设长一点便于人工干预 |
| `gap_ms` | `inter_gap_ms_x10` | 50（=500ms） | 1~250 | **路间静默时间** ×10 ms：自动浇灌是"一路一路"浇的，先开阀 Z1 浇完关阀，再开 Z2。若 Z1 刚关就立刻开 Z2，水管内的水压尚未卸掉，会形成"水锤"（瞬间压力冲击，可能震坏阀体或接头）。因此两路切换之间要**停一小段时间什么都不做**，让水压自然泄掉。值太小换路冲击大，太大则浪费时间 |
| `tmo_ch` | `per_channel_timeout_s` | 90 | 30~120 | **单路软超时**（秒）：安全兜底。正常情况一路阀浇完会自己结束；但若水泵堵转、阀卡住或传感器异常导致这一路**迟迟浇不完**，程序不能一直傻等。超过该秒数即判定异常、强制停止并报错，防止"水漫金山"。称"软"超时是因为还有一层代码写死的硬上限（120s 不可调），本字段是用户可调的那层 |
| `tmo_all` | `total_timeout_s` | 480 | 60~600 | **总任务软超时**（秒）：整个自动浇灌流程（所有启用路全部浇完）超过该秒数仍未结束，强制终止并告警，兜底防止整体失控 |
| `selftest` | `selftest_pulse_ms` | 50 | 10~200 | **自检脉冲宽度**（ms）：每次上电后系统会先"自检"——快速把每路阀和泵**通一下电再关掉**，通过检测电流是否正常来判断负载有没有接好、是否断线。这个"通一下"的时长就是本字段。太短检测不到电流，太长会真的出水。默认 50ms |

#### HMI 参数（人机交互阈值与显示）

| 短名 | C 字段 | 默认 | 范围 | 含义 |
|---|---|---|---|---|
| `long_ms` | `long_press_ms_x10` | 100（=1000ms） | 30~300 | **长按门限** ×10 ms：按键区分"短按"与"长按"的临界时间。按下并保持**超过**此时长（默认 1000ms）即被识别为"长按"，用于"确认/进入"这类需要避免误触的操作。小于该时长松手则判为短按 |
| `hold_ms` | `hold_press_ms_x10` | 300（=3000ms） | 100~500 | **超长按门限** ×10 ms：比长按更长的一档（默认 3000ms），通常绑定"恢复出厂"等危险/不可逆操作，用更长的按持时间进一步防误触 |
| `contrast` | `oled_contrast` | 128 | 0~255 | **OLED 对比度**：控制屏幕像素亮暗。值越大屏幕越亮（过大会整体发白、字迹模糊），越小越暗（过小会看不清）。128 为适中值；若屏幕显示偏淡可调大到 160~200，偏浓/发白可调小到 80~100 |
| `log` | `log_level` | 2 | 0~3 | **日志等级**：控制串口输出信息的多少。等级越高输出越多：`0`=E 只打印错误；`1`=W 打印警告+错误；`2`=I 打印信息+警告+错误（默认）；`3`=D 打印全部含调试细节（最啰嗦）。排查问题临时调 3，正常使用保持 2 |

#### 只读字段

| 短名 | 说明 |
|---|---|
| `hw` | 硬件版本号（`hw_version`，BCD 编码），当前 V3.1，**不支持 `cfg set`**，仅在 `cfg dump` / `ver` 中显示 |

#### 修改单个字段（立即持久化）

```text
cfg set <name> <value>   → 修改配置并立即写入 EEPROM
cfg set duty[0] 40        → 修改第 1 档占空比为 40%
cfg set log 3             → 修改日志等级为 3（Debug）
```

- **内存与存储同步**：`cfg set` 会同时修改 RAM 中的运行时副本，并**立即调用 `App_Config_Save()` 写入 EEPROM 双 Bank**，掉电/复位后仍然保留，无需再手动 `cfg save`。
- 成功提示 `[I] ok: cfg set (persisted to EEPROM)`。
- 越界值会被自动钳位（clamp）到合法范围（例如 `duty[0] 99` 被夹到 95）。
- `cfg save` 保留为兼容命令，因 `set` 已自动落盘，单独执行 `cfg save` 等价于把当前 RAM 再写一次（无副作用）。

```text
cfg save    → 显式再写一次 EEPROM（set 已自动持久化，此命令一般无需使用）
cfg load    → 重新从 EEPROM 读取到 RAM（丢弃 RAM 中未落盘的改动）
cfg reset   → 恢复出厂设置（二次确认，见下）
```

#### 开机加载与"存储未初始化"提示

- 开机时 `App_Config_Init()` **直接从 EEPROM 双 Bank 读取**较新的有效配置到 RAM。
- 若 EEPROM 为空或双 Bank 均损坏（如首次烧录、更换新 EEPROM），则加载代码内置默认值 `g_factory_config`，并在串口打印警告：

```text
[W] config: storage not initialized, using factory defaults
```

- 此时 `cfg dump` 会显示 `src=factory`、`update_count=0`，表示当前用的是默认值、存储尚未初始化。执行一次 `cfg set`（自动落盘）或 `cfg save` 即可完成存储初始化。

#### 恢复出厂设置（二次确认）

```text
> cfg reset
[W] cfg reset: wipe EEPROM to factory defaults?
[W]   send 'y' to confirm, any other key to cancel

> y
[I] ok: factory reset done (EEPROM wiped to defaults)
```

- `cfg reset` 后**不立即执行**，需再输入 `y`（或 `yes`）确认；输入其它任意内容则取消，EEPROM 不变。
- 确认后执行 `App_Config_FactoryReset()`：将 EEPROM 双 Bank 全部恢复为代码内置默认值（`g_factory_config`），并连续写两次刷新 A/B 两 Bank。

## 5. 常用联调顺序

```text
debug
help
key test
key test off
status
valve open 1
valve open 2
pump 30
pump off
valve close
status
```

安全说明：`pump <非零>` 会检查至少一路阀（Z1~Z5）已打开；否则返回干转互锁错误 `FM_ERR_013_PUMP_NO_POWER`。联调建议先 `valve open 1`（任一路阀）再 `pump`。
